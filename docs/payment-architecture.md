# 支付流程架构设计

## 概述

本文档描述抢票系统支付流程的架构设计，采用 RocketMQ 事务消息 + 延迟消息的方案，实现"订单创建 + 消息发送"的原子性以及支付超时自动取消机制。

**核心原则**：支付系统只负责**存储和返回支付状态**，业务系统通过 RocketMQ 回查机制主动查询。

## 核心组件

| 组件 | 职责 | 端口 |
|------|------|------|
| **秒杀服务** | Redis 锁座、调用订单服务 | 8083 |
| **订单服务** | 创建订单、发送消息、主动查询支付状态 | 8087 |
| **支付系统** | 存储/返回支付状态（被动服务） | 7500 |
| **场次服务** | 数据库座位状态更新 | 8084 |
| **RocketMQ** | 消息队列、事务消息协调 | 9876 |

## 消息定义

| Topic | Tag | 类型 | 发送者 | 消费者 | 作用 |
|-------|-----|------|--------|--------|------|
| TPP_ORDER_TOPIC | ORDER_PAID | 事务消息 | 订单服务 | 订单服务、场次服务、秒杀服务 | 支付成功后更新订单、座位状态 |
| TPP_ORDER_TOPIC | CANCEL | 延迟消息 | 订单服务 | 订单服务、秒杀服务 | 15 分钟后超时取消订单 |

## 流程设计

### 1. 锁座与订单创建 (`/seckill/lock`)

```
┌─────────────────────────────────────────────────────────────────┐
│  前端请求 /seckill/lock                                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  秒杀服务                                                         │
│  ├─ 1. Redis 锁座（状态 0→1）                                    │
│  ├─ 2. 调用订单服务 createPendingOrder                          │
│  └─ 3. 调用支付系统创建支付订单                                  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  订单服务                                                         │
│  └─ 调用 sendMessageInTransaction() 发送半消息                   │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  RocketMQ Broker 收到半消息                                      │
│  └─ 回调 OrderTransactionListener.executeLocalTransaction()     │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  executeLocalTransaction() 执行本地事务                          │
│  ├─ 1. 创建订单（数据库）                                        │
│  ├─ 2. 发送延迟消息（CANCEL，15分钟）                             │
│  └─ 3. 返回 UNKNOWN（等待支付确认）                                │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  响应前端                                                         │
│  └─ 返回订单信息 + 支付URL，前端重定向到支付系统                  │
└─────────────────────────────────────────────────────────────────┘
```

**关键点**：
- 订单是在 `executeLocalTransaction` 中创建的，不是在 `createPendingOrder` 中创建
- 秒杀服务在订单创建后调用支付系统，获取支付URL返回给前端
- 这样确保 checkLocalTransaction 回查时，支付记录已存在

### 2. 支付成功流程

```
┌─────────────────────────────────────────────────────────────────┐
│  用户完成支付（模拟）                                              │
│  └─ 调用支付系统模拟接口                                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  支付系统                                                         │
│  └─ 更新 payment_record.status → SUCCESS                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  RocketMQ 回查订单服务                                            │
│  ├─ TransactionListener.checkLocalTransaction()                 │
│  ├─ 主动查询支付系统 GET /payment/query                          │
│  └─ 如果返回 SUCCESS：提交事务消息                                │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  RocketMQ 投递消息给消费者                                        │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  OrderPaidConsumer 处理                                          │
│  ├─ 主动查询支付系统状态                                          │
│  ├─ 如果已支付：                                                 │
│  │   ├─ Redis 确认购买（状态 1→2）                                │
│  │   └─ 更新订单状态 → 已支付                                    │
│  └─ 如果未支付：跳过（等待下次回查）                              │
└─────────────────────────────────────────────────────────────────┘
```

### 3. 超时取消流程

```
┌─────────────────────────────────────────────────────────────────┐
│  15 分钟后                                                       │
│  └─ CANCEL 延迟消息到期                                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  OrderCancelConsumer 处理                                        │
│  ├─ 检查订单状态                                                 │
│  ├─ 如果已支付：忽略                                             │
│  └─ 如果未支付：取消订单 + 释放座位                              │
└─────────────────────────────────────────────────────────────────┘
```

### 4. RocketMQ 事务消息回查机制

```
┌─────────────────────────────────────────────────────────────────┐
│  场景：需要确认订单支付状态                                        │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  Broker 回查订单服务                                              │
│  └─ TransactionListener.checkLocalTransaction()                 │
│      ├─ 主动查询支付系统 GET /payment/query                      │
│      ├─ 返回 SUCCESS → 提交事务消息                              │
│      ├─ 返回 PENDING → 返回 UNKNOWN，继续回查                    │
│      └─ 返回 NOT_FOUND/FAILED → 回滚事务消息                     │
└─────────────────────────────────────────────────────────────────┘
```

```
  │         │          │─查询支付状态───────────────>│           │

  │         │          │             │             │─更新座位状态──>│
```

**事务消息两个阶段**：

| 阶段 | 方法 | 说明 |
|------|------|------|
| 阶段1 | `executeLocalTransaction(msg, arg)` | 执行真正的本地事务：创建订单、发送延迟消息 |
| 阶段2 | `checkLocalTransaction(msg)` | 回查：查询支付系统状态，决定提交/回滚/继续回查 |

## 数据一致性保证

| 场景 | 保证机制 |
|------|---------|
| 订单创建失败 | 本地事务回滚，Redis 座位锁释放 |
| 消息发送失败 | RocketMQ 回查机制 |
| 支付状态确认 | 回查时**主动查询**支付系统 |
| 订单超时未支付 | 延迟消息自动取消 |

## 设计原则

1. **支付系统是被动服务**：只存储和返回支付状态，不主动通知
2. **业务系统主动查询**：通过 HTTP 查询支付状态
3. **支付系统是真实来源**：支付状态以支付系统为准

## 幂等性处理

### 订单服务 OrderPaidConsumer
```java
// 检查订单是否已是支付状态
if (OrderStatus.PAID.getCode().equals(order.getStatus())) {
    log.info("订单已是支付状态，跳过");
    return;
}
```

### 场次服务 OrderPaidConsumer
```java
// 检查座位是否已售出
Seat existingSeat = seatMapper.selectOne(...);
if (existingSeat != null && orderNo.equals(existingSeat.getOrderNo())) {
    log.info("座位已处理，跳过");
    return;
}
```

## 注意事项

1. **支付系统不提供回调**：业务系统主动查询支付状态
2. **支付状态唯一来源**：以支付系统返回的状态为准
3. **回查机制**：TransactionListener 调用支付系统查询接口
4. **消息统一**：只使用 ORDER_CREATED 消息，移除 PAY_SUCCESS 消息
5. **幂等性**：所有消费者都实现了幂等性检查
